因子挖掘与回测评估——从 AI 生成到统计证伪
数据层就绪后，核心问题变成：策略从哪里来？回测结果能不能信？AI 在这两个环节的介入方式截然不同——挖掘环节是“加速器”，评估环节必须是“刹车”。

LLM 驱动的因子挖掘
传统人工因子挖掘依赖研究员专业素养且成本高昂。2026 年，基于 LLM 的自动化因子挖掘已经形成了多条成熟技术路线。清华团队发表于 AAAI 2026 的框架将 LLM 与蒙特卡洛树搜索结合，利用 LLM 的指令遵循和推理能力在 MCTS 驱动的探索中迭代生成和精炼符号化 Alpha 公式，并以回测的量化反馈引导搜索方向。广发金工团队的实测数据显示，在沪深全市场以 10 个交易日为换仓周期，Qwen3-VL-235B 生成的因子 IC 均值达到 2.95%。

华泰金工团队的“因子工厂”系统采用了多智能体分工架构：Factor GPT 负责构建与优化因子公式，多智能体质量检查器负责筛选，适应度评估模块负责打分，思维进化机制负责迭代。这种架构的关键设计是将“生成”与“评估”严格分离——生成智能体追求多样性和覆盖率，评估智能体以统计严格性为准绳，两者不共享同一套目标函数，避免生成过程被评估标准反向污染。

回测过拟合的统计防线
回测的致命诱惑在于：你测试的候选模型越多，找到一个匹配历史噪声的模型的概率就越大。2026 年的量化工程实践已经形成了一套统计证伪的技术栈。Deflated Sharpe Ratio（DSR）对多重检验进行惩罚，DSR 低于 0.5 的策略通常被判定为过拟合。Probability of Backtest Overfitting（PBO）通过组合对称交叉验证估计选择过程本身的过拟合概率。

更系统的方案是分层评估协议。AlgoXpert 框架将评估分为三个阶段：In Sample 阶段关注稳定参数区域而非单一最优点，以多数通过和灾难性否决规则控制泄漏；Out of Sample 阶段在参数锁定的严格条件下测试，禁止进一步调参。GT-Score 则将表现、统计显著性、一致性和下行风险整合为单一目标函数，在 walk-forward 验证中显著改善了泛化比率。

对于程序员而言，最实用的操作原则是：先确定预测时间戳，再验证每一个特征和标签是否只使用了该时点可得的信息。归一化统计量只在训练集上计算，标签不能与测试期重叠，特征不能包含事后修订的经济数据。这些原则不复杂，但违反其中任何一条，回测结果就只是一份漂亮的幻觉。

AI 在挖掘与评估中的角色分离
一个重要的架构原则是：绝不让 AI 直接决定下单。QuantAgent 的设计哲学明确区分了“LLM 负责信息处理与研究辅助”和“传统量化引擎负责交易执行”。在因子挖掘环节，LLM 的价值在于快速探索符号搜索空间和生成可解释的公式；在回测评估环节，统计证伪必须由确定性代码完成，因为 LLM 天然倾向于为已有结论寻找合理化解释。
